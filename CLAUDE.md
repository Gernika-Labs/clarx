# intention/ui

An intention-driven design system. Three layers: philosophy (docs), reference implementation (`packages/ui`), and an AI rules layer (`content/docs/ai-rules/`).

## Monorepo layout

```
packages/ui/src/          — reusable semantic UI components (production code)
apps/docs/                — documentation site (Next.js 15 + fumadocs)
apps/docs/content/docs/   — MDX pages (edit here to change doc content)
apps/docs/components/demos/ — live demo components referenced by MDX pages
apps/docs/lib/            — shared utilities for the docs app
journal/                  — architecture decisions and audits
```

## Component pattern (`packages/ui/src/`)

Every component follows this exact shape — read `badge.tsx` as the reference:

1. Import shared types from `./tokens.ts` (`Intent`, `Appearance`, `Size`)
2. CVA variants mapping semantic props → Tailwind classes
3. Optional `KEYWORD_MAP` for named states (e.g. `keyword="failed"`)
4. Component function — pure, no side effects, no context
5. Export from `index.ts`

`tokens.ts` is the vocabulary of the system. Start there when working on components.

## Adding a component

1. Create `packages/ui/src/[name].tsx` — follow `badge.tsx` pattern
2. Export from `packages/ui/src/index.ts`
3. Create demo files in `apps/docs/components/demos/[name]-demo.tsx`
4. Add demos to `apps/docs/lib/mdx-components.ts`
5. Create `apps/docs/content/docs/components/[name].mdx`
6. Add the page to `apps/docs/content/docs/meta.json`

## Adding a doc page

1. Create MDX file in `apps/docs/content/docs/`
2. Add it to `apps/docs/content/docs/meta.json` in the right position

## How MDX demos work

MDX pages reference demo components by name, e.g. `<BadgeIntentDemo />`.  
These are registered in `apps/docs/lib/mdx-components.ts`.  
That file is the only place to add or remove demo components.  
`apps/docs/app/docs/[[...slug]]/page.tsx` is only a route — it just imports `mdxComponents` from lib.

## Template strings

`apps/docs/lib/templates.ts` is the single source of truth for the CLAUDE.md, Cursor, and AGENTS.md templates. The search dialog copy actions and the template MDX pages both read from this file. Do not duplicate these strings elsewhere.

## Known workaround

`apps/docs/app/source.ts` has a `typeof rawSource.files === 'function'` check.  
This handles a version mismatch: `fumadocs-mdx@11` returns files as a lazy function but `fumadocs-core@15` expects a plain array.  
**Remove when `fumadocs-mdx` is upgraded to v12+.**
