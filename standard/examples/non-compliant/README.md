# Non-Compliant Example — Common Violations

This example shows a repo structure with common problems that harm AI navigability.
Each violation maps to a specific Clarx rule failure.

**Score: ~30/100 — two hard failures, multiple warnings.**

---

## Directory structure

```
my-app/
├── src/
│   ├── components/
│   │   ├── Button.tsx
│   │   └── Dashboard.page.tsx    # B4 ✗ — primitives and pages mixed
│   ├── utils.ts                  # D4 ✗ — utility dump (80 exports, mixed domains)
│   ├── helpers.ts                # D4 ✗ — another dump file
│   ├── api/
│   │   └── routes.ts             # C2 ✗ E1 ✗ — 600 lines, all routes in one file
│   └── .next/                    # C1 ✗ HARD FAILURE — generated dir in source tree
├── test/
│   └── Button.test.tsx           # B5 ✗ — not co-located or mirrored
├── config/
│   └── app.ts
├── README.md                     # marketing copy only, no structure info
├── package.json                  # no exports field → E5 ✗
├── node_modules/                 # (present in source tree listing)
├── dist/                         # (not declared as generated)
├── coverage/
├── .cache/
├── tmp/
├── scratch/
└── old/                          # D1 ✗ — 13 meaningful root entries
```

**Root has 13 meaningful entries** — 3 over the D1 limit.

---

## What's wrong and why it matters to AI agents

### C1 — Hard failure: `.next/` inside source tree
The `.next/` directory is generated by Next.js but lives inside `src/`. An AI agent scanning the repo will load thousands of generated files into context before finding any real source code. Score is capped at 50 regardless of everything else.

**Fix:** Add `.next` to `clarx-manifest.json` under `generated`, or move it outside `src/`.

---

### O1 — Hard failure: no guidance file
No `CLAUDE.md`, `AGENTS.md`, or `clarx-manifest.json`. An AI agent has no way to know where to make changes, how to verify them, or which directories are generated. Score is capped at 50.

**Fix:** Run `clarx init` to generate a starter manifest, then add a `CLAUDE.md`.

---

### D1 — Root has 13 meaningful entries
`node_modules`, `dist`, `coverage`, `.cache`, `tmp`, `scratch`, `old` are all visible at the root. An agent asked to "find the source code" has to filter through noise.

**Fix:** Delete unused directories. Declare generated ones in the manifest.

---

### D4 — `utils.ts` and `helpers.ts` are dumping grounds
Both files mix unrelated functions — string formatting, date parsing, API calls, auth helpers — in one place. An agent can't predict what's in them without reading everything.

**Fix:** Split into domain-specific files: `formatting.ts`, `auth.ts`, `date.ts`.

---

### C2 — `routes.ts` is 600 lines
One file handles all routes. Any change to any route requires loading the entire file into context.

**Fix:** Split into one file per domain: `auth.routes.ts`, `user.routes.ts`, `billing.routes.ts`.

---

### B4 — Primitives and pages in the same directory
`Button.tsx` (a reusable primitive) and `Dashboard.page.tsx` (an application screen) live in `src/components/`. An agent adding a new component doesn't know whether to look here for reusable parts or application logic.

**Fix:** Separate into `src/components/` (primitives) and `src/pages/` (screens).

---

### B5 — Tests not co-located or mirrored
`test/Button.test.tsx` is in a flat `test/` directory at the root, not co-located with `Button.tsx` or in a mirrored `__tests__/` directory.

**Fix:** Move to `src/components/Button.test.tsx` or `src/components/__tests__/Button.test.tsx`.

## How to fix it — in order

1. `clarx init` — generates a manifest, declares generated dirs
2. Add `CLAUDE.md` — removes O1 hard failure
3. Move `.next/` out of `src/` — removes C1 hard failure
4. After those two: score jumps above 50 and real pillar scores become visible
5. Split `utils.ts` and `helpers.ts` into domain files
6. Split `routes.ts` into per-domain route files
7. Reorganize components vs pages
8. Move tests to co-located or mirrored structure
