### gqloom-01 — bug fix

This library converts strings between naming conventions when it generates GraphQL type and field names. Two of those converters disagree about separators at the start of a string: converting "_leading" to PascalCase yields "Leading", dropping the underscore, while converting the same input to SCREAMING_SNAKE_CASE yields "_LEADING", keeping it. Trailing separators are handled inconsistently for the same reason.

Make the two converters agree. Leading and trailing separators should be ignored by both, so that "_leading" becomes "Leading" and "LEADING" respectively, and "trailing_" becomes "Trailing" and "TRAILING". Inner separators must keep working exactly as they do today, and the existing behaviour for every other input must not change.

**Contamination:** Not present in the issue tracker or commit history: the asymmetry was found by executing both converters against separator-prefixed inputs during task authoring, not by reading the project's own reports.

### gqloom-02 — refactor

One of the string-conversion helpers in this project contains a conditional expression whose two branches are identical — both compute the same value, so the condition decides nothing. Remove the redundancy.

The observable behaviour of the helper must not change for any input. Do not alter its signature, its name, or where it is exported from, and do not rewrite the surrounding helpers while you are there.

**Contamination:** The redundant ternary is visible in the current source and is not referenced by any commit message or issue; an agent must locate it by reading the code rather than by recalling a fix.

### gqloom-03 — small feature

This project has helpers that convert a string into PascalCase and into SCREAMING_SNAKE_CASE. Add a third that converts into kebab-case, following the same conventions the existing ones follow: it should accept space-, hyphen-, and underscore-separated input as well as camelCase, split camelCase boundaries into separate words, lower-case every word, and join with single hyphens. "helloWorld", "hello_world", and "Hello World" should all produce "hello-world", and empty input should produce an empty string.

Place it alongside the existing converters and make it reachable from the package's public entry point in the same way they are.

**Contamination:** kebab-case conversion does not exist anywhere in the repository at the pinned commit, so it cannot be recalled from the project's own source; the required behaviour is stated in the prompt rather than recoverable from history.

### gqloom-04 — cross file

Several places in this project build a compound GraphQL type name by converting two or more fragments to PascalCase and concatenating them, for example combining a table name with a column name, or a field name with a key. The same two-step pattern is repeated in more than one package.

Introduce a single shared helper that takes any number of string fragments, converts each to PascalCase, and joins them, then use it at the existing call sites that currently perform that conversion-and-concatenation by hand. The helper belongs next to the other string converters and must be reachable from the public entry point the same way they are. Generated names must come out byte-identical to what they are today, and the full test suite must still pass.

**Contamination:** No such helper exists at the pinned commit and no issue proposes one; the duplication was located by reading call sites across packages during task authoring.
